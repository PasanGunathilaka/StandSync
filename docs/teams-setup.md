# Teams setup

StandSync runs the Teams SDK **on the existing Fastify server** via a custom
`IHttpServerAdapter`. There is one HTTP process and one port: Fastify serves
`/health`, the `/dev/*` endpoints, and the Teams messaging endpoint
(`/api/messages`) side by side.

```
                       ┌──────────────────────────── Fastify (PORT) ───────┐
Teams channel ──POST──▶│ /api/messages ─ FastifyHttpServerAdapter          │
                       │                   └─▶ Teams SDK App              │
                       │                        ├─ on('message')          │
curl / dev:post ──────▶│ /dev/standup  ─────────┤                         │
                       │ /dev/approve/:id ──────┤   runStandupPipeline()   │
                       │ /dev/reject/:id        │   executeBatch()         │
                       │ /health                │                         │
                       └───────────────────────────────────────────────────┘
```

Both entry points call the **same** `runStandupPipeline` and `executeBatch`, so
the fallback demo path cannot drift from the real one.

## Prerequisites

```powershell
winget install Microsoft.devtunnel
devtunnel user login
```

## 1. Start the tunnel

Teams must reach your machine over HTTPS.

```powershell
devtunnel host -p 3978 --allow-anonymous
```

`--allow-anonymous` is required: Teams calls the endpoint without tunnel-layer
credentials. Copy the public URL (e.g. `https://abc123-3978.aue.devtunnels.ms`)
and leave the tunnel running for the whole session — the URL changes each time
you restart it unless you create a persistent tunnel.

## 2. Create the bot (Teams Developer Portal)

[dev.teams.microsoft.com](https://dev.teams.microsoft.com) is the current
recommended route. It needs no Azure subscription.

1. **Tools → Bot management → + New bot**, name it `StandSync`, **Add**.
2. Open the bot → **Client secrets → Add a client secret**. **Copy the value
   immediately** — it is shown once. Copy the _Value_, not the Secret ID.
3. **Endpoint address**: `https://<your-tunnel>/api/messages`
4. Note the **Bot ID** (a GUID) from the bot's overview.

<details>
<summary>Alternative: Azure Bot resource</summary>

Azure Portal → **Create a resource** → **Azure Bot** → Multi Tenant. After
creation, **Configuration** gives the Microsoft App ID, **Manage Password**
creates the secret, and **Channels** must have **Microsoft Teams** added. Set
the messaging endpoint to `https://<your-tunnel>/api/messages`. Requires an
Azure subscription and rights to create resources.

</details>

## 3. Configure StandSync

```
MICROSOFT_APP_ID=<Bot ID from step 2.4>
MICROSOFT_APP_PASSWORD=<client secret Value from step 2.2>
MICROSOFT_APP_TENANT_ID=            # leave blank for a multi-tenant bot
TEAMS_ALLOWED_CONVERSATION_ID=      # filled in at step 6
```

StandSync logs a warning and disables Teams entirely if the id/secret are unset —
the `/dev/*` endpoints keep working regardless.

## 4. Register the app and build the package

In the Developer Portal: **Apps → + New app** → name `StandSync` → complete
**Basic information**, then **App features → Bot** → select your StandSync bot →
scopes **Team** and **Group chat** → **Save**.

Then build the sideloadable package:

```powershell
npm run teams:package     # → appPackage/build/standsync-teams.zip
```

This substitutes `TEAMS_APP_ID` and `MICROSOFT_APP_ID` into the manifest and zips
it with the icons. If `TEAMS_APP_ID` is unset it generates one and prints it —
add it to `.env` so repackaging keeps the same app identity.

> The manifest targets schema **1.19**. Supported range is 1.19–1.30; anything
> older (the original 1.17) is rejected at upload. Icons are generated by
> `npm run teams:icons` and are required — Teams rejects a package without them.

## 5. Sideload

Teams → **Apps** → **Manage your apps** → **Upload an app** → **Upload a custom
app** → pick `standsync-teams.zip` → **Add to a team** → the standup channel.

The Developer Portal's **Preview in Teams** button does the same thing.

> **If "Upload a custom app" is not shown, your tenant blocks sideloading.** That
> is an administrator policy — see "Tenant blockers". Do not attempt to work
> around it; use the `/dev/*` demo path instead.

## 6. Lock StandSync to one channel

StandSync **fails closed**: with `TEAMS_ALLOWED_CONVERSATION_ID` unset it ignores
every message. Post anything in the target channel and read the log:

```
WARN: TEAMS_ALLOWED_CONVERSATION_ID is not set, so StandSync is ignoring this
      message. To enable this channel, set
      TEAMS_ALLOWED_CONVERSATION_ID=19:abc...@thread.tacv2
```

Copy that id into `.env` and restart. This two-pass setup is deliberate — a bot
that writes to a real Jira project should not act on any channel it is added to.

## 7. Smoke test

```powershell
npm run seed:jira     # resets TES-41 / TES-42 / TES-43
npm run dev
```

1. Post in the channel: `Yesterday I completed TES-41. Today I am working on TES-42. TES-43 is blocked because I am waiting for API credentials.`
2. StandSync replies in-thread with the proposal card.
3. Click **Approve All** → card becomes **Applying to Jira…** → then the result card.
4. Check Jira: TES-41 Done, TES-42 In Progress, TES-43 has a `[StandSync]` comment.

## Configuration reference

| Variable                        | Purpose                                                                |
| ------------------------------- | ---------------------------------------------------------------------- |
| `MICROSOFT_APP_ID`              | Bot ID. Unset ⇒ Teams disabled, `/dev/*` still works.                  |
| `MICROSOFT_APP_PASSWORD`        | Client secret **Value**.                                               |
| `MICROSOFT_APP_TENANT_ID`       | Single-tenant bots only; blank for multi-tenant.                       |
| `TEAMS_APP_ID`                  | Teams app identity GUID — distinct from the bot id.                    |
| `TEAMS_ALLOWED_CONVERSATION_ID` | The one channel StandSync listens to. Unset ⇒ ignores everything.      |
| `TEAMS_MESSAGING_ENDPOINT`      | Defaults to `/api/messages`.                                           |
| `TEAMS_ALLOW_UNAUTHENTICATED`   | Local testing only. Skips Teams token validation. Never in production. |
| `APPROVAL_POLICY`               | `anyone` (default) or `author_only`.                                   |

## Tenant blockers

Sideloading is an administrator-controlled setting.

- **Teams admin center** → Teams apps → **Setup policies** → Global → enable
  _Upload custom apps_. Requires the Teams Administrator role.
- Some tenants additionally block new app registrations or consent.

**If any of this is blocked, StandSync remains fully demonstrable.** The `/dev/*`
endpoints run the identical pipeline and executor:

```powershell
npm run seed:jira
npm run dev
npm run dev:post                                          # proposals, nothing written
curl -X POST http://127.0.0.1:3978/dev/approve/<batchId>  # applies to Jira
```

## Troubleshooting

| Symptom                                                       | Cause                                                                                                                                    |
| ------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------- |
| `AADSTS700016: Application with identifier ... was not found` | Wrong app id/secret, or the bot is not registered in this tenant.                                                                        |
| Manifest rejected on upload                                   | Schema version below 1.19, missing icons, or `id` not a valid GUID.                                                                      |
| Card appears but buttons do nothing                           | Tunnel dropped, or the endpoint address no longer matches the tunnel URL.                                                                |
| Bot never replies                                             | Conversation id not in `TEAMS_ALLOWED_CONVERSATION_ID` (step 6), or the message contained no Jira keys.                                  |
| `EADDRINUSE :3978`                                            | Orphaned dev server: `Get-NetTCPConnection -LocalPort 3978 -State Listen \| ForEach-Object { Stop-Process -Id $_.OwningProcess -Force }` |
| Every request 401                                             | Credentials unset and `TEAMS_ALLOW_UNAUTHENTICATED=false`. Expected — set real credentials.                                              |
